## Problem

Cause `class name` of `missing_tokens.py`: 331 lost oracles on the nine projects (247 by this cause alone; jsoup 92,
eec 86, esapi 50, crawler 37). The classes offered at the start of an expression are built by
`updateHashMapOfTypeDeclarationPathIdentifiers` (the types of the test file, its imports, its package). Six defects:

1. `java.lang` was never offered (`String.valueOf`, `Math.abs`, `Long.MAX_VALUE`,
   `assertThrows(IllegalArgumentException.class, ...)`): the collectors of the JDK classes of `TokensUtils` are not
   called anywhere.
2. The member types were never found by name: in `getTypeDeclarationsFromCompilationUnitAndName` the loop over the
   nested types started with the condition `!targetTypeDeclaration.isEmpty()`, false at the start, so it never ran:
   after `Document.OutputSettings.` (jsoup) or `Grid.` (`FastGrid`, eec) nothing followed.
3. The imports of member types (`import org.jsoup.nodes.Document.OutputSettings`, and the static imports of member
   types) were looked up as a file `Document/OutputSettings.java` or as a package, and found nothing. The records
   were left out of the imports (only classes, interfaces and enums were added).
4. The classes of the package of the test class were read recursively (`Files.walk`): the classes of the
   subpackages were offered, though not visible without an import; the interfaces were left out (their constants,
   `x instanceof SomeInterface`).
5. The classes generated by the pipeline (`…STARSplitTest`, `…STARNormalizedTest`, `…STARSplitTestPrefix`) were
   offered, in every package that has tests (dozens of names per step).
6. After `instanceof`, the classes of the previous step were kept (the context of the expression tested), not the
   classes in scope (crawler `asm instanceof SiteMap`, esapi `scrubbers.get(0) instanceof NewlineLogScrubber`).

## Fix

The classes visible by their simple name, following the rules of Java:

- the types declared in the test file, the member types of the test class at any depth;
- the imports: one type (every kind: class, interface, enum, record, annotation), a member type
  (`import a.B.Inner`, `import static a.B.Inner` for a static member type), all the types of a package (`import a.b.*`,
  the package itself only), all the member types of a class (`import a.B.*`, `import static a.B.*`);
- the types of the package of the test class (the package itself only, interfaces included);
- the public classes of `java.lang` (the package itself, not `java.lang.reflect`), unless a class of the same name is
  already visible (declared, imported or in the same package: it shadows the one of `java.lang`); read once per JDK
  selection;
- never the classes generated by the pipeline (the original test class stays: it is a class of the package).

After `instanceof`, the classes visible at the root are offered. The member types are found by name at any depth
(not the local classes of a method).

The classes of the focal class (its imports and package) are still added, as before (they are not visible in the
test class unless imported there too; left as is, out of the scope of this step).
